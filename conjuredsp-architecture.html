Processes & sandboxes

Why two apps instead of one? A DAW-hosted AU extension runs under a strict App Sandbox that forbids spawning external binaries. Claude Code, git, and uv all need to fork — so they live in a companion app. The two processes never call each other directly; they communicate only through a shared App Group container.

04

Audio render path — the real-time hot path

What happens on every render callback, inside ConjureDSPExtensionAudioUnit.swift's internalRenderBlock. This runs on the audio thread, so it avoids heap allocation and unbounded waiting. Steps 6–8 happen within a single FFI call into Rust.

⚡ Hard real-time. numpy arrays are pre-allocated once at allocateRenderResources() · parameters are lock-free AtomicU32 · the spectrogram feed is an SPSC ring buffer · per-segment temp pointer arrays use withUnsafeTemporaryAllocation (stack, not heap) · the kernel never blocks — a backend swap uses try_lock and falls back to passthrough on contention.
1
DAW invokes the render block
Host calls internalRenderBlock with a timestamp, frame count, and output buffer list.
2
Pull input audio
Pulls the main bus, plus sidechain bus 1 if the host has audio routed there — sets the sidechainConnected flag. Handles in-place buffers.
3
Capture transport state
Reads tempo, beat position, time signature, play state → dsp_kernel_set_transport(). Also stored to a brief-locked snapshot (TransportPushManager) that custom UIs poll at ~30 Hz.
4
Walk the AU event list
Iterates the real-time event list; parameter-automation events split the block into segments. MIDI events in the list are skipped — the DSP kernel has no MIDI path.
5
Apply parameter events
Each automation event → dsp_kernel_set_parameter(). The DAW's real-world value is normalised to 0–1 via the parameter metadata first.
6
Cross the FFI — process each segment
dsp_kernel_process_with_sidechain() passes input/output/sidechain channel pointers into Rust. One call per segment between events.
7
Rust kernel dispatches to the active backend
Python: copy audio into pre-built numpy rows → rebind ctx slices → call process(ctx) → copy back.  WASM: wasmtime exports, fuel-metered.  Fallback: passthrough copy on any error.
8
License & demo gate — inside the same call
Before output is written, the kernel checks an AtomicBool mirrored from SubscriptionStatus. Unlicensed demo mode passes ~60 s of audio, then silences output.
9
Return to the DAW
The kernel fills the SPSC spectrogram & telemetry ring buffers during processing; the Swift render block then hands the output buffers back to the host. The UI drains those ring buffers on its own timer.
05

DSP kernel & pluggable backends

The Rust crate conjure_dsp is the engine room. kernel.rs is a façade over a Backend trait — three implementations satisfy it, and the kernel can swap between them at runtime.

Kernel — owns & coordinates
Backend selection
Holds the active Box<dyn Backend>; phased hot-swap on script reload (declick envelope)
kernel.rs
Parameter store
16 slots, normalised 0–1 in an AtomicU32 array; metadata cached as JSON
params.rs
Ring buffers
SPSC lock-free — input / output scope feeds + sparse telemetry
ring_buffer.rs
License & demo state
Ed25519 verify, grace window, demo countdown
license.rs
STATE channel
Atomically-swapped JSON buffer — bundle-private persistence
Backend trait — initialize() · process() · param_metadata() + lifecycle
kernel routes the active segment to one implementation
PythonBackend
pyo3-embedded free-threaded CPython 3.14 (no GIL). numpy interop; process(ctx) receives pre-allocated 2-D float32 arrays. Instant load.
python_backend.rs
WasmBackend
wasmtime executes wasm32-wasip1 modules. Fuel metering caps runaway loops. I/O via memory exports.
wasm_backend.rs
PassthroughBackend
Bit-exact input→output copy. The safety net whenever a script fails to load or traps at runtime.
passthrough_backend.rs
The same kernel binary also exposes profiling (dsp_kernel_profiler_*), benchmarking (dsp_kernel_benchmark_process), memory accounting, and NAM (Neural Amp Modeler) tone-model slots — all over the C FFI.

Subscription & licensing

A Paddle subscription model with a Cloudflare Workers backend. The server signs short-lived tokens; the app verifies them locally with an embedded public key — so it works offline for up to a 7-day grace window.

Cloud
Paddle → Cloudflare Workers
Webhooks update a D1 SQLite store. /activate and /verify sign a JSON payload with the Ed25519 private key.
server/ — activate.ts · verify.ts · webhook.ts · token.ts
→
App — Swift
SubscriptionManager
Stores the token in the App Group container; refresh loop (15 min active / 1 h grace). Demo mode = ~60 s of audio.
Model/SubscriptionManager.swift · SubscriptionAPI.swift
→
Kernel — Rust
license.rs
Verifies the Ed25519 signature with the embedded public key, checks the grace window, and sets the audio-thread AtomicBool licensed flag.
Status drives the audio path directly: Active and GracePeriod grant full processing; anything else falls back to demo mode, which silences output after 60 seconds (see render step 8).

Export — preset as a standalone AUv3

Licensed users can export any preset as its own standalone AUv3 plugin. The pipeline copies a pre-built template AU, patches it, injects the preset, and signs it — the exported plugin then runs freely.
