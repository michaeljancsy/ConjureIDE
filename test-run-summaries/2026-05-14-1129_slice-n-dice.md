## Design

Faithful reproduction of the Pluggo "Slice-n-Dice" granular delay. Continuously records mono input into a ~20 s circular numpy buffer; every sample, the latest cycle (32 contiguous slices) is addressable by slice index, and a 32-element `STATE.slices` pattern (each entry 0..31) routes step → source slice. The 5 AU params cover the docs surface exactly — `total_time_quarter` (32–4000 ms, log, default 1974 matching the screenshot), `sync_mode` (Free/Host), `note_value` (13-option choice spanning whole..1/64t), `dry_level`, `wet_level`. The 32-element multislider lives in the bundle-private STATE channel (so the UI writes it, the DSP reads it, neither burns an AU param slot), and the custom HTML UI is a 285-line painted-canvas multislider + Forward/Reverse/Random pattern buttons + the 5 cdp-* controls.

## What worked

- `save_preset(scaffold_ui=true)` produced the full manifest + entry script + ui shell in one shot — no per-file fixup needed afterward.
- STATE channel slotted in cleanly as the home for the 32-int pattern array; the agent reached for it on first instinct after reading `get_docs("state")`.
- `dsp_probe` + `get_parameters` round-trip caught a low-output-RMS scare; agent reasoned about it correctly (probe length < cycle length at default settings) without false alarm.
- `smoke_test_ui` passed first try: 5 cdp-* components all bound, `ready` fired in ~63 ms, zero JS errors. The agent did not need any redo of the UI.
- Defaults honor the docs verbatim — `total_time_quarter` default 1974 ms exactly matches the screenshot in the PDF, which is the level of attention to source-of-truth detail you'd want.

## Errors + recoveries

Agent re-probed at 100 ms quarter time, confirmed `out_peak ≈ wet * in_peak`, moved on. No tool error, no doc lookup needed for recovery.

## Friction findings

- [skill] First dispatch wasted ~$0.78 because the MCP port shifted between `/try-it`'s port-poll and the `claude -p` invocation: poll grabbed `55668` from a freshly-written instance JSON, but by dispatch time the AU had re-registered on `55670` (the older JSON got swept). The subagent's init line said `mcp_servers: [{name: 'conjuredsp', status: 'failed'}]` and it produced a design-only digest. The skill should validate the discovered port via `curl POST /mcp initialize` immediately before writing the MCP config + dispatching, and re-poll if the handshake fails.
- [bug] User pressed play on the saved preset and the AU extension crashed via Rust panic during render — `EXC_CRASH (SIGABRT)` at `dsp_kernel_process_with_sidechain` → `panic_cannot_unwind` → `abort`. [Crash report](file:///Users/michaeljancsy/Library/Logs/DiagnosticReports/ConjureDSPExtension-2026-05-14-113309.ips). Original config was 48000 Hz / 1ch mono; subsequent attempts under stereo, then mono with the same audio file, then UI-driven state writes during playback, all failed to reproduce. The crash report carries only "abort() called" — Rust's panic message goes to stderr, which the AU extension's stderr isn't captured anywhere readable (not unified log, not the .ips body, not the host app's terminal). Root cause unknown. Mitigation: a debug-only panic-to-file logger is filed in a separate PR so the next Rust panic in any preset/path will leave a forensic file the `.ips` doesn't. A complementary `catch_unwind` at the FFI boundary would let the kernel degrade to passthrough instead of aborting, but per the user's instruction we're not adding it until we have at least one captured panic message — today the AU dies on any render-side Rust panic.
- [ux] `dsp_probe` default sample length (~48k) is shorter than the cycle of many useful delay/granular presets at typical settings. Either the probe should accept a `min_samples` / `cycle_periods` knob, or the response should hint "fewer than 1 full processing cycle covered" so the agent doesn't have to deduce it from the RMS shape. (Agent recovered on its own here, but the inference cost was real.)
- [meta] Agent picked Python over Rust for a 32-slice granular delay despite the "default to Rust" guidance — vectorized numpy indexing into the ring buffer ($write_idxs$ / $read_idxs$ via `np.arange`) is a strong fit, and the agent justified it implicitly via the indexing math. Worth tracking whether the "Rust default" guidance needs a "unless you need vectorized scatter/gather over a long buffer" carve-out.
- [meta] Pattern of UI strategy: cdp-* declarative controls *plus* a hand-rolled painted-canvas multislider, with the two kept in sync via `ConjureDSP.state.slices`. The agent cited the docs' "hand-rolled bindings need a declarative twin" note as the reason — that guidance is doing real work and probably worth keeping prominent.
