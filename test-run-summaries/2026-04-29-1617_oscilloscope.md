## Design

Tanh soft-clipper / saturator publishing channel-0 output as `vector_telemetry`. Two params: `Drive` 0–24 dB into tanh, `Mix` dry/wet via the `crossfade()` helper. Custom UI: full-width `<cdp-scope>` above two `<cdp-knob>` controls. Same DSP idea as the prior "Scope Drive" run, slightly leaner (no Output trim, knobs instead of sliders).

## What worked

- `save_preset` passed first try — no compile error this time. Avoided the `db_to_gain` f64 trap by using `crossfade(dry, wet, mix_val)` instead of mixing f32 and f64 manually.
- `scaffold_ui=true` pre-set `audioFrames: true` in the manifest, so the scope received frames without an extra step.
- `read_bundle_file` → `write_bundle_file(manifest.json)` lets the agent inspect what scaffold emitted before overwriting — useful pattern.
- Static validation in-turn on every `write_bundle_file` — no async wait loop.

## Friction findings

- [scaffold] `save_preset(scaffold_ui=true)` writes `manifest.json` without a `params` array even though it knows the `params!{}` block from the source. Authors lose v2-schema's "correct defaults during slow Rust compile" benefit until they hand-write it.
- [ux] `save_preset` tool description doesn't mention that `scaffold_ui=true` flips `audioFrames: true`. Right default; missing surface area.
- [docs] No clear guidance on `db().min().max()` vs `param(min,max).unit("dB")` — both work, but it's not obvious which preserves the `dB` unit in the knob value readout.
- [ux] `smoke_test_ui` pass message can't note that scope/meter UIs need live audio for visual confirmation. Authors may take "pass" as "looks right."
- [meta] Second consecutive run on this prompt landed on a tanh saturator. Strong prior — docs / examples could nudge toward sidechain detectors, lookahead waveform views, delay-tap visualization to broaden the demo space.
