## Design

Stereo biquad lowpass driven by `<cdp-xy>` — X controls cutoff (20 Hz–20 kHz, log), Y controls resonance (Q 0.707–12, inverted so up = more resonant). A collapsed `<details>` panel exposes the two sliders as a fallback for fine-tune. Per-channel `Biquad::process_sample` with coefficients recomputed per block from `BiquadCoeffs::lowpass`; stereo state held in `persist!([Biquad; 2])`.

## What worked

- **`save_preset(scaffold_ui=true, ui_width=360, ui_height=280)` landed correct dims in one call.** No follow-up `write_bundle_file('manifest.json')` needed to fix dimensions — this is the verification path the PR (#315 / Asana 1214756850520774) was built to prove.
- `audioFrames: false` (the new flipped default) landed correctly — the UI is pure-control, no meters/scopes, no need to opt in.
- `<cdp-xy param-x="Cutoff" param-y="Resonance">` binding resolved cleanly via loose name match.
- `dsp_probe` with `sine 500Hz` confirmed the lowpass actually attenuates and produces no NaN/Inf.

## Errors + recoveries

- First `smoke_test_ui` flagged content_overflow (24px past the requested 280pt height). Recovered by tightening paddings, header font, and pad height (200→180) — re-ran smoke_test_ui and got a clean pass at 360×280 exactly.

## Friction findings

- [ux] `control_explicit_size_too_small` lint over-fires on `cdp-xy::part(puck)`. The 60px "grabbability" minimum is calibrated for slider thumbs; an XY pad's hit area is the entire pad, not the puck. Subagent's verbatim feedback: "the warning was confusing — 'users may not be able to grab this control' is misleading when the control's hit area is the entire pad."
- [docs] No documented inline-default example for `freq()` in the `params!` macro doc. Subagent had to discover `.default(1000.0)` chaining works because `freq()` appears in the filters doc without a default. A one-line `freq().default(1000.0)` example would close that.
- [ux] `save_preset(scaffold_ui=true)` response says "Starter ui/index.html written" but doesn't summarize what's IN the starter, so the first `write_bundle_file('ui/index.html')` is blind whether it's replacing meaningful content or boilerplate. A one-liner ("scaffold contains an auto-panel and placeholder heading") in the response would help.
