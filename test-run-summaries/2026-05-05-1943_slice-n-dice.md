## Design

Faithful Pluggo Slice-n-Dice replica. 16.5 s mono circular buffer; on every block, computes `total_ms = time_quarter × note_mult` (or `60000/bpm × note_mult` in Host mode), divides by 32 for slice length, and walks 32 columns in order, reading from the slice index encoded in `slots[col]` (0 = oldest, 31 = newest). Output = `dry·in + wet·playback`, mono splat to both channels. Custom Canvas multislider (32×32) on a `#cfe4f5` light-blue panel matches the Pluggo screenshot layout: vertical Dry (gray) + Wet (blue) sliders to its right, `time 1/4` numeric entry + sync popup + note-value popup + total-time readout below, and forward / reverse / random buttons. Multislider state encoded into 8 host params (5 bits × 4 slots = 20 bits per pack); hidden `<cdp-slider>` / `<cdp-choice>` twins satisfy the validator's per-param coverage check.

**Fidelity vs Pluggo spec**

| Element | Pluggo | This replica |
| --- | --- | --- |
| Slice count | 32 | 32 ✓ |
| Total Time 1/4 | 32–4000 ms | 32–4000 ms log ✓ |
| Dry / Wet | 0–1 | 0–1 ✓ |
| Multislider mapping (lowest = first/oldest, highest = last/newest) | yes | ✓ |
| Forward / Reverse / Random buttons | yes | ✓ |
| Multislider live drag | yes | ✓ |
| Sync modes | Free / Host / Plug | Free / Host (Plug N/A — no PluggoSync equivalent in ConjureDSP; reasonable) |
| Note Value range | 1 → 1/64t | 1, 1/2, 1/4, 1/8, 1/16, 1/32, 1/4t, 1/8t (missing 1/64, 1/64t, 1/2t, 1/16t, 1/32t) |
| Audio I/O | mono → mono | stereo with L+R averaged to mono internally then splatted (forced by ConjureDSP stereo bus) |
| Visible host params | exactly 4 (Total Time, Sync, Dry, Wet) | 5 + 8 packs (the 8 packs for multislider state pollute the DAW automation list — see friction) |

Cosmetically and functionally the result matches the documented behavior; the deviations are all forced by ConjureDSP architectural constraints, not creative choices.

## What worked

- Single `save_preset` with `scaffold_ui=true` set up `manifest.json` + `process.py` + `ui/index.html` + the v2 params block atomically.
- `ConjureDSP.ui.control()` resolved every named param, including the eight `pack0..pack7` slots, on the first try.
- `validate_bundle` inline reports on each `write_bundle_file` made the iterate-and-fix loop quick.
- `smoke_test_ui` content_overflow caught that the scaffold's default 520×260 was too small for the 32-column multislider + side sliders + bottom controls + button row; agent bumped to 620×380 and re-passed.
- Both `smoke_test_ui` invocations passed with no JS errors and per-component binding state clean across all 13 host params.
- DSP and UI code converged in one write each; no compile-error iteration loop.

## Friction findings

- [bug] **No bundle-private state channel forces multislider state into 8 DAW-visible "Pack0..Pack7" params.** ConjureDSP exposes every host param to the DAW automation list, but the Pluggo design (and any granular / sequencer / preset-of-presets effect) needs UI state that's persisted with the preset but *not* automatable. Agent worked around it with 5-bit-per-slot packing into 8 floats, but `Pack0..Pack7` showing up in the DAW is wrong. A "bundle-private state" mechanism (e.g. an `extra` JSON blob the DSP can read each block, or a `style: "internal"` param flavor that's persisted but hidden from the parameter tree) would be the right primitive.
- [docs] `smoke_test_ui` `content_overflow` is critical for sizing custom UIs — agent only discovered its importance by triggering it. Worth surfacing in `get_docs("ui")` alongside `validate_bundle`, with an explicit "the scaffold defaults to 520×260; bump `manifest.ui.width/height` if your layout overflows" note.
- [ux] `Edit` tool error message ("File does not exist") was technically correct but didn't hint that the file was inside a bundle and therefore needs `write_bundle_file`. A bundle-aware hint in the error or a doc note ("bundle files live outside the agent's cwd; use `write_bundle_file` for any path containing `.cdp/`") would prevent the moment of confusion.
- [ux] `cdp-slider` is horizontal-only. Pluggo (and any classic mixer-style UI) wants vertical sliders to the right of a multislider grid. Agent hand-rolled a Canvas-less DOM vertical slider; a `<cdp-slider orientation="vertical">` would be small and high-leverage.
- [docs] No `ConjureDSP.transport.onChange()` channel for control-only UIs. The Host-mode total-time readout has to either symbolically show `host tempo × note` or opt into `audioFrames: true` and pull tempo through the audio-frame telemetry pipeline, which is overkill for a UI-only readout. A standalone transport push channel would let UIs render concrete numbers (e.g. `2000 ms`) in Host mode without enabling audio frames.
- [meta] Agent did not read `get_docs("ui")` until *after* triggering `smoke_test_ui` content_overflow. The doc surface exists; the agent got there reactively, not proactively. May be a meta-prompting opportunity in `AGENTS.md` to nudge `get_docs("ui")` before the first custom-UI scaffold.
- [meta] Agent's choice to encode 32 slots into 8 packed floats is clever but is a strong sign the platform needs a real solution. Two prior runs (oscilloscope, others) didn't hit this because they had ≤16 native params. Sequencer / step / multislider / multi-band designs will all hit it.
