Single-param gain stage. `GAIN` (−24…+24 dB, default 0) drives `db_to_gain(GAIN)` and multiplies each input sample. About as minimal as it gets — and on a deliberately open-ended prompt the agent landed on the canonical "first-preset" example in 4 turns flat. Useful baseline for the cleanup-pass build (`d6061ec`) — confirms the merged work didn't regress the simple Rust path.

## Friction findings

- [skill] Fresh subagent session pays a `ToolSearch` round-trip tax to learn `save_preset`'s schema before any real work — the deferred-tool system surfaces tool *names* in the system-reminder list but not their JSON Schema. Pre-loading the core ConjureDSP MCP tool schemas (or at least `save_preset`, `get_script`, `get_docs`, `compile_and_run`) would save a turn on every plugin task.
- [docs] System-reminder header says "Script loaded (python, has PARAMS)" but `AGENTS.md` instructs the agent to default to Rust and always `get_script` before assuming. Mild tension between the trustworthy-looking header and the don't-trust-it rule. A small "(advisory only — call get_script to confirm)" hint in the header text would resolve it.
- [docs] `get_docs("params")` returns one ~5 KB dump that covers Python AND Rust together. For a single-language task half the response is dead tokens. A `language` filter (e.g. `get_docs("params", language="rust")`) or split topics (`params.rust` / `params.python`) would tighten it.
- [scaffold] Saved bundle's manifest has `params[0].key = ""` (empty string) for the Rust preset. The `name` is "Gain" and the lookups still resolve, but an empty key field is suspicious — should be `"gain"` (lowercased name) for consistency with the Python path.
