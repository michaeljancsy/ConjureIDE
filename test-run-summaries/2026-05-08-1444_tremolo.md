## Design

A textbook amplitude-modulation tremolo in Rust: a single bundle-static `Lfo` ticked once per frame, sine output mapped to a unipolar `[0, 1]` envelope, then blended toward unity by `(1 - depth)` so `depth=0` is bypass and `depth=1` swings full 0→1. Same gain applied to all channels per frame. Two params: `Rate` (0.1–20 Hz, log curve, default 4 Hz) and `Depth` (0–1, default 0.7). No custom UI.

## What worked

- `get_docs("oscillators")` had a matching frames-outer / tick-once-per-frame Rust example that lifted directly into `process()`, including the explicit warning not to tick per channel.
- `get_docs("params")` was clear about builder chaining (`.min().max().default()`) and `freq()`'s defaults, so no second lookup was needed.
- Single-shot `save_preset` with `source=` did the full round-trip — bundle written, kernel reloaded, AU parameter tree populated. No follow-up `compile_and_run`.

## Friction findings

- [docs] The `oscillators` doc shows `inputs[ch][i] * mod_val` with a bipolar sine as "tremolo," but that's actually ring modulation — at audio-rate `Rate` the sign flips per cycle. A one-line nudge in the example ("for tremolo, want a unipolar envelope: `lfo*0.5+0.5`") would prevent a really common newcomer bug.
- [docs] `freq()` defaults to 20 Hz–20 kHz (audio-rate), so using it for an LFO rate requires overriding both `min` and `max`. A `lfo_rate()` builder, or at least a doc note pointing people at `param(min, max)` for sub-audio rates, would feel more natural.
- [docs] `Lfo::new()` being `const` (so it works in `static mut`) is great but easy to miss without the existing doc note — keep that prominent.
- [skill] First subagent run lost the MCP connection partway through (host app + appex both exited mid-run). Re-launching cleared the stale instance file and a second dispatch worked. `/try-it` doesn't currently re-probe the port mid-run or warn that the AU process disappeared — silent friction.
- [skill] Setup gap: this machine had no `cargo`/`rustup` and no `rust/python-dist/` bundle. CLAUDE.md lists both as one-time setup but `/try-it` doesn't pre-check. Pre-flight check + auto-run of `setup-python.sh` (and a clear "rustup not installed" error before launching xcodebuild) would save several rebuild loops.
