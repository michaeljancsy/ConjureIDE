### WASM module convention

The WASM module must export:
- `memory` — linear memory
- `process(input_ptr: i32, output_ptr: i32, channels: i32, frame_count: i32, sample_rate: f32)` — DSP function

Memory layout: channels sequential, each `frame_count` floats. Base offset at 1024 to avoid null page.

## Key design decisions

1. **WASM for all compiled languages** — provides sandboxing, fuel-based execution limits, and a unified runtime
2. **Backend trait pattern** — `PythonBackend` and `WasmBackend` share the same interface; kernel doesn't know which is active
3. **`&mut self` on `process()`** — wasmtime's `TypedFunc::call` requires `&mut Store`, so Backend::process takes `&mut self`. This works because the FFI layer uses `*mut DSPKernel` raw pointers.
4. **wasi-sdk via setup script** — downloaded on first use, not bundled (too large). Same pattern as `setup-python.sh`.
5. **System rustc for Rust scripts** — users already have rustc since it's needed to build ConjureDSP itself
6. **Fuel budget: 1M instructions per callback** — graceful error on exhaustion, falls back to passthrough
7. **WASM memory base offset at 1024** — avoids the null page in WASM linear memory
